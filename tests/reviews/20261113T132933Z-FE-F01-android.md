# FE-F01 Android black-box evidence review

## Environment

- Revision: base `0092b0ba38d9a3813d558454154ce075ec71cd82` plus the uncommitted FE-F01 worktree revision supplied in the test packet.
- Platform: Android only, AVD `Srastemsya35` (`emulator-5554`).
- Installed package: `fefu.prime.srastem`; package installation was verified by the timestamped run report.
- Staging: the supplied discovery-v1 service. Results came from the app UI; no backend behavior was assessed.

## Acceptance observations

- **AC-01 / F01-01 — PARTIAL.** From the Feed tab, the single-device card opened FE-F01. The filter screen showed “Что ищем?” and “Вы выбираете вместе на одном устройстве”. PLACE showed no date control; EVENT showed “Дата события”. Kind and category selection each displayed one active chip. For PLACE, selecting “Места для проверки свайпов”, budget `100000` ₽, and party size `1` opened the results screen with 20 “Стендовый вариант” entries. For EVENT, date `2026-11-14`, category “События для проверки свайпов”, budget `100000` ₽, and party size `1` submitted and opened the results screen, which said “Подходящих вариантов пока нет. Измените фильтры.” The UI request path passed, but the event result set was empty, so event matching could not be confirmed.
- **AC-02 / F01-01 — PASS.** Submitting budget `-14` showed a red budget field and “Введите неотрицательный целый бюджет”. With a budget supplied, party size `0` showed “Укажите число человек от 1” and submission remained on the filter screen. Screenshots: [negative budget](../evidence/FE-F01/20261113T132800Z-android/03-negative-budget-error.png), [zero party size](../evidence/FE-F01/20261113T132800Z-android/04-zero-party-size-error.png).
- **AC-03 / F01-02 — PASS.** “Изменить фильтры” reopened the current PLACE filter values (selected category, budget `100000`, party size `1`). Changing the category to “Места для проверки свайпов” and submitting opened a fresh results list of 20 variants. Screenshot: [restored values](../evidence/FE-F01/20261113T132800Z-android/06-restored-filter-values.png); [updated results](../evidence/FE-F01/20261113T132800Z-android/05-place-candidate-results.png).
- **AC-04 — PARTIAL/PASS.** The screen showed the requested heading and single-device context. The date control appeared for EVENT and was absent for PLACE. UI Kit visual integration was not independently compared to the updated Figma reference. Screenshots: [single-device filters](../evidence/FE-F01/20261113T132800Z-android/01-single-device-filters.png), [event kind/date](../evidence/FE-F01/20261113T132800Z-android/02-event-kind-date-control.png).
- **AC-05 — PARTIAL/PASS for public feature documentation.** `shared/src/commonMain/kotlin/fefu/prime/srastem/feed/FEATURE.md` describes `GET /v1/catalog/categories`, `GET /v1/feed/candidates`, filter validation, and the FE-F02 swipe-controller boundary. Runtime criteria are separately covered above.

## Gaps and result

FE-F01 UI behavior is substantially observed on Android. The event candidate request returned no variants for the selected staging date/category, so its matching semantics remain unverified. Figma comparison was not performed. Overall acceptance is **PARTIAL**, not a full PASS, because AC-01 event matching and the AC-04 design-system comparison remain unverified.
