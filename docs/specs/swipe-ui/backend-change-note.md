# Пометка для бэкенда: персональные фильтры комнаты

**Статус:** целевое изменение по решению пользователя; отдельно от текущей реализации. [UI-маршрут](README.md) и [экран фильтров](13-room-filters.md).

## Что сейчас

[Discovery v1](../../contracts/discovery-v1.md) задаёт `POST /rooms/{id}/start` с одним объектом `{filters: FeedFilters}`, который отправляет владелец. Сервер нормализует `partySize` до размера комнаты. [FE-F01](../feed-v1/implementation.md#fe-f01--фильтры-подборки) позволяет редактировать фильтры только организатору; остальные ждут в лобби. В [Lobby v2](../../contracts/lobby-v2.md) есть персональные веса категорий, но они не являются полным набором персональных фильтров и применяются после общих фильтров комнаты.

## Что нужно изменить

1. Дать каждому участнику комнаты отправить и при необходимости изменить **свои** фильтры до начала подбора: тип, категории, бюджет на человека, дату события в применимых случаях. Определить запрос, ответ, права доступа и идемпотентность.
2. Хранить персональный выбор на сервере и отдавать автору его сохранённые значения и состояние готовности комнаты. Чужие конкретные фильтры и бюджет раскрывать только если это явно согласовано; для UI достаточно статуса готовности каждого участника.
3. Сформировать единый пул после объединения ответов участников. Зафиксировать, кто запускает подборку, нужны ли ответы всех и что происходит при выходе участника или тайм-ауте.
4. Определить **правило объединения** отдельно для типа подборки, категорий, даты и бюджетов. Сейчас оно не задано; нельзя подменять его пересечением, суммой или средним по предположению. Уточнить, что показывать при несовместимых ответах и пустом результате.
5. Обновить `Room` snapshot, long polling, контракт старта, ошибки и тесты; сохранить одинаковые состав и порядок сформированного пула для всех участников. Затем обновить мобильную FE-спеку и UI-состояния отправки/ожидания.

## Зависимость UI

Фрейм Figma [280-10805](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10805) пока показывает только организатора и кнопку запуска. Для персонального сценария нужны макеты участника, отправленных фильтров, ожидания остальных и конфликта фильтров. До их появления экран 13 — визуальный референс полей, но не завершённый эталон всего нового поведения.
