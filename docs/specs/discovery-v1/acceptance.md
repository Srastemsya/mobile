# Приёмка бэкенда

Проверять HTTP API по [контракту релиза](../../contracts/discovery-v1.md). Использовать изолированный стенд с опубликованными и неопубликованными объектами, минимум четырьмя участниками для комнаты и одним посторонним, событиями обоих типов входа, местом с неизвестной ценой и пулом более 20 карточек. Организатор события может быть одним из тестовых пользователей. Для проверок границ времени предусмотреть управляемое время или данные с заранее заданными временными границами.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| D00-01 | Запросить dev-код по телефону и по email. Подтвердить код с ведущим нулём, завершить регистрацию именем и датой рождения | Доставка не нужна. До завершения каталогу возвращается `403 PROFILE_INCOMPLETE`, после завершения тот же JWT открывает каталог и комнаты. Повторный вход по тому же контакту возвращает тот же userId и завершённый профиль. |
| D00-02 | Проверить неверный код, раннюю повторную отправку, заменённый код и два параллельных verify одного challenge с разными ключами | Неверный код — `422 OTP_INVALID`, ранняя отправка — `429`, заменённый код — `410`. Только одна проверка выдаёт сессию. |
| D00-03 | Обновить сессию, повторить refresh с тем же ключом, затем использовать старый refresh с новым ключом. Проверить поддельный JWT и JWT после logout | Повтор возвращает ту же пару. Повторное использование отзывает семейство. Поддельный и отозванные токены отклоняются каталогом и комнатами. |
| D00-04 | Запустить базовую конфигурацию с включённым mock OTP | Identity отклоняет конфигурацию запуска вне dev. |
| D01-01 | Запросить открытия без координат, затем запросить поиск с фильтрами первой подборки | `200`, стабильный порядок подборок, фильтры дают только подходящие объекты. На пустом наборе массивы пустые. |
| D01-02 | Запросить карточку из списка и детали события по двум маршрутам | Одна пара `EVENT/id`, совпадают координаты и детали для того же пользователя. Категория присутствует в справочнике. |
| D02-01 | Опубликовать событие, повторить запрос с тем же ключом, затем с изменённым телом | Оба одинаковых запроса дают один ID и исходный статус. Изменённое тело даёт `409 IDEMPOTENCY_CONFLICT`. Другой аккаунт сразу видит одну карточку в подходящих афише, карте и новой выдаче свайпов. |
| D02-02 | Опубликовать OPEN с вместимостью, REGISTRATION без неё, платную запись, событие с неверными координатами или чужой обложкой | Каждый запрос отклонён. Ни одна запись не появляется в новых выдачах. Валидный OPEN не содержит счётчиков. Валидный REGISTRATION начинается с нуля подтверждённых. |
| D02-03 | Запросить события по локальной дате на стыке суток, цене и наличию мест, пройти страницы | Граница даты рассчитана по Владивостоку, неизвестная цена исключается при заданном потолке. При фильтре мест остаётся только REGISTRATION с остатком. Стабильный набор выдаётся без дублей. |
| D02-04 | Два пользователя параллельно запрашивают последнее место | Один получает `201`, другой `409 EVENT_FULL` со счётчиками. Повтор победителя с тем же ключом возвращает исходный ответ, с новым ключом — ту же активную запись и `200`. Остаток равен нулю. |
| D02-05 | Посторонний читает список или снимает запись. Владелец дважды снимает запись и читает список | Постороннему `403`. Снятие освобождает ровно одно место, записи нет в активном списке. Снятый участник получает `409 REGISTRATION_REMOVED` при новой попытке. |
| D02-06 | Прочитать детали до начала, в момент начала и в момент окончания. Попытаться записаться в момент начала | Фазы `UPCOMING`, `ONGOING`, `PAST`. В момент начала `canRegister=false`, запись даёт `409 EVENT_CLOSED`. |
| D03-01 | Запросить EVENT и PLACE с бюджетом, включая кандидата ровно по бюджету и кандидата с неизвестной ценой | Выдаётся выбранный тип. Граничная цена проходит, неизвестная исключается. Без бюджета неизвестная цена допустима. |
| D03-02 | Пройти все страницы выдачи, повторить курсор, затем использовать его после истечения | Страницы не пересекаются, повтор даёт ту же порцию, последняя страница содержит `nextCursor=null`. Истёкший курсор даёт `409 CURSOR_EXPIRED`. |
| D03-03 | Создать комнату, пригласить четырёх участников всего, запустить. Прочитать комнату посторонним | Все участники видят одинаковый пул и зафиксированный состав. Посторонний получает `404`. Новый участник после запуска не входит. |
| D03-04 | Попытаться завершить неполный проход. Изменить голос, завершить полный проход, переподключиться | Неполный проход даёт `409 INVALID_STATE`. После завершения голос не меняется. GET восстанавливает свой последний выбор и признак завершения без чужих голосов. |
| D03-05 | Дать одной карточке два лайка из четырёх, завершить раунд конкурентными запросами | Матча нет. Появляется один новый пул без ранее показанных карточек либо `EXHAUSTED` при пустой выдаче. Повтор завершения возвращает текущий snapshot. Новый голос по старому раунду даёт `409 STALE_ROUND`. |
| D03-06 | Дать двум карточкам по три лайка. Последние два участника завершают проход параллельно | Все видят один и тот же `MATCHED`. Побеждает более ранняя из карточек. При различии голосов выигрывает карточка с большим числом лайков. |
| D03-07 | Отключить участника до завершения, переподключиться, затем дождаться срока комнаты без завершения | Состав не меняется. После 30 минут GET возвращает `CLOSED`, голосование не меняет состояние. |
| D03-08 | Открыть long poll организатора через Nginx, вступить со второго устройства по ссылке | Ожидание завершается `200 Room` с большей версией и новым участником. Токена приглашения в ответе нет. |
| D03-09 | Открыть long poll на текущей версии, проголосовать или завершить раунд параллельным запросом | Ожидающий клиент получает обновлённую версию. При повторном запросе со старой версией ответ приходит сразу. Личные голоса другого участника отсутствуют. |
| D03-10 | Держать long poll без изменений до 25 секунд, затем повторить. Проверить запрос постороннего и отзыв сессии во время ожидания | Nginx пропускает `204` без тела, следующий запрос работает. Посторонний получает `404` сразу. Отозванная сессия получает `401` при завершении ожидания. |
| INT-00 | Выполнить документированную команду Compose на чистом локальном окружении, затем повторить запуск | Все сервисы готовы, миграции и dev-данные применены без дублей. Регистрация, афиша и комнаты доступны через Nginx. PostgreSQL, Redis и Kafka не публикуют порты наружу. |
| INT-01 | Запросить защищённые маршруты без токена и с незавершённым профилем | `401 UNAUTHENTICATED` и `403 PROFILE_INCOMPLETE` соответственно. |
| INT-02 | Отключить собственную БД на изолированном стенде и восстановить её | `/health` возвращает 503 во время недоступности и 200 после восстановления. В ответе и журналах нет учётных данных. |

В отчёте указать версию стенда, тестовые данные, выполненные сценарии, фактические статусы и ссылки на неизменённые отчёты прогонов по [правилам тестирования](../../../workflow/rules/testing.md). Критерии проверяются по публичным результатам API.
