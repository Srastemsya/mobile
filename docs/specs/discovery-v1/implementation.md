# Спецификация разработки

Обязательные API и правила ошибок описаны в [контракте релиза](../../contracts/discovery-v1.md). Применяются [архитектура, готовность, сопровождение контрактов и правила тестов](../../../workflow/rules/index.md).

## Сервисы и локальный запуск

| Сервис Python/FastAPI | Владеет | Маршруты через Nginx |
|---|---|---|
| `identity` | Аккаунты, профили, сессии и OTP | `/v1/auth/*`, `/v1/me`, `/v1/me/registration` |
| `catalog` | Открытия, категории, места, события, записи и вместимость | `/v1/home`, `/v1/catalog/*`, `/v1/events*` |
| `swipes` | Одиночные выдачи, приглашения, комнаты, раунды и голоса | `/v1/feed/*`, `/v1/rooms*`, `/v1/room-invites/*` |

У каждого сервиса собственная PostgreSQL с отдельными учётными данными, миграциями и томом. Redis используется для TTL-кэшей, OTP, лимитов, проверки статуса сессий и уведомлений о версиях комнаты. Запись авторизационных ключей принадлежит identity. Разделить доступ к ключам авторизации, кэша и комнат через ACL. PostgreSQL остаётся источником истины для профилей, каталога и состояния комнаты.

Kafka используется для событий об изменениях каталога и инвалидации кэша. Событие каталога публикуется через transactional outbox и содержит ID объекта и ревизию, потребители обрабатывают повторы идемпотентно. Новый пул в swipes получает свежий снимок кандидатов одним внутренним HTTP-запросом к catalog. Этот синхронный вызов нужен на границе создания пула для видимости публикации сразу после успеха. Голоса и чтение комнаты не обращаются к catalog. Данные уже выданного пула сохраняются в swipes.

Добавить корневые `compose.yaml` и `compose.dev.yaml`, пример переменных и README запуска. Локальная команда `docker compose -f compose.yaml -f compose.dev.yaml up --build -d --wait` поднимает Nginx, сервисы, PostgreSQL, Redis и Kafka, применяет миграции и загружает dev-данные идемпотентно. Единственный опубликованный порт по умолчанию — `127.0.0.1:8080` для Nginx. Для эмуляторов документировать адрес хоста. Mock OTP и синтетические данные включаются dev-конфигурацией. Базовый Compose не включает mock OTP.

Nginx маршрутизирует запросы по префиксам, передаёт заголовки авторизации и ключ идемпотентности, не кэширует ответы API. Для long polling отключить буферизацию и задать `proxy_read_timeout 35s`. Не включать query с токенами приглашений или заголовки авторизации в журналы. Каждый FastAPI сервис предоставляет readiness `/health`, Compose healthcheck, настройку восстановления и административный доступ по профилю MatchWear.

## BE-D00 · Dev-авторизация и регистрация

[Макеты регистрации и поля формы](../../design/auth.md) · [HTTP-контракт](../../contracts/discovery-v1.md#вход-и-регистрация)

Пользователь проходит реальный серверный сценарий входа и завершения регистрации с замоканной доставкой кода. Реализовать identity с OTP по телефону и email, повторной отправкой, одноразовым погашением challenge, созданием аккаунта и заполнением имени и даты рождения. Подготовить синтетические контакты для минимум пяти участников и отдельный контакт для новой регистрации. Хранить аккаунты в PostgreSQL. Защищать OTP, хранить проверочные значения refresh и отслеживать действительность сессий в Redis с TTL. При недоступности состояния сессии не выдавать доступ. Подпись JWT принадлежит identity, остальные сервисы проверяют её публичным ключом. После заполнения профиля и после отзыва сессии обновить состояние, используемое всеми сервисами.

## BE-D01 · Открытия и общий каталог

[Дизайн открытий](../../design/home.md) · [Пользовательские маршруты](../../design/ux-personas-scenarios.md#4-пользовательские-сценарии-user-journeys)

Пользователь без готового плана видит подборки даже без разрешения геолокации. Подготовить справочник категорий, конфигурацию упорядоченной карусели и стендовый каталог мест, активностей и событий Владивостока. Реализовать `/home`, чтение категорий, поиск из подборки без текста, детали по `CatalogRef` и выборку по границам карты. Использовать один источник идентичности и проекции карточек. Обновление категорий или публикация инвалидируют затронутые записи Redis. Поля зрителя и актуальная вместимость формируются при запросе. Для пустой выдачи возвращать успешный ответ, пригодный для пустого состояния фронтенда.

## BE-D02 · Афиша, публикация и запись

[Дизайн афиши](../../design/events.md) · [Детали события](../../design/event.md)

Организатор публикует событие с точкой и понятными условиями участия. Посетитель видит стоимость и доступность до принятия решения. Реализовать чтение афиши и деталей, публикацию и API записей. Хранить время в UTC и зону отдельно. Валидировать тип входа, категорию, время, точку и право на обложку. В транзакции создавать событие и фиксировать успешный идемпотентный ответ. После успеха обеспечить видимость из всех оговорённых точек входа, включая чтение сразу после публикации. Кэш не должен скрывать только что опубликованное событие.

Запись, снятие и изменение заполненности атомарны. Ограничить число активных записей вместимостью, установить уникальность для пары пользователь–событие и проверять владельца при запросах списка и снятии. Снятие сохраняет статус и время снятия. Повтор с исходным ключом воспроизводит ранее успешный ответ. Повторное чтение возвращает текущее состояние. Права для карточки вычисляются на сервере и совпадают с фактическими ограничениями маршрутов.

## BE-D03 · Свайпы на одном и нескольких устройствах

[Дизайн ленты](../../design/feed.md) · [Сценарий компании друзей](../../design/ux-personas-scenarios.md#c-компания-друзей-не-знает-чем-заняться)

Компании нужен выбор по общему бюджету без повторного просмотра карточек. В одиночном режиме зафиксировать фильтры и порядок выдачи на срок курсора. Возвращать данные для карточки и перехода в детали. Локальная отмена и первый лайк обрабатываются клиентом.

В комнате сохранять состав, раунд, решения, завершения, использованные карточки и монотонную версию snapshot. Токен приглашения непредсказуемый и не попадает в журналы. Старт и вход должны сериализоваться относительно друг друга. Голосование, завершение и переход состояния проверяют актуальность раунда и членство. Параллельные завершения приводят к одному результату или одному новому раунду. Переподключение восстанавливает личный прогресс через GET. Перезапуск процесса сохраняет состояние комнаты и её срок. После фиксации новой версии уведомить ожидающие запросы через Redis. При подписке повторно прочитать версию, чтобы закрыть гонку между чтением и подпиской. Перед тайм-аутом повторить проверку версии в PostgreSQL, чтобы потерянное уведомление не потеряло обновление. Отмена HTTP-запроса освобождает подписку. Настроить стендовые наборы для проверки строгого большинства, ничьей, пустого пула и обновления подборки.
