# Приёмка · Комната v2

Проверять HTTP API по [контракту комнаты v2](../../contracts/lobby-v2.md) на изолированном стенде discovery-v1 с применёнными пакетами v2. Нужны минимум четыре участника, один посторонний, каталог с категориями не менее трёх типов и пул, достаточный для двух полных раундов. Сценарии v1 (D03-*) остаются обязательными регрессионными проверками.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L01-01 | Участник отправляет веса в LOBBY, перечитывает комнату, переподключается | `200 Room` с собственными `preferences` и `hasPreferences=true`; чужие веса отсутствуют. После переподключения набор восстановлен. |
| L01-02 | Отправить вес вне диапазона, неизвестную категорию и дубль категории | Каждый запрос — `422 VALIDATION_ERROR` с указанием поля, набор не изменён. |
| L01-03 | Повторить PUT с тем же набором, затем с изменённым | Повтор не меняет `version`. Изменение поднимает `version`, ожидающий long poll второго участника получает snapshot с обновлённым `hasPreferences` без значений весов. |
| L01-04 | PUT весов после старта и посторонним | `409 INVALID_STATE` и `404 NOT_FOUND` соответственно. |
| L01-05 | Участник без весов стартует комнату | Старт успешен, отсутствие весов трактуется нейтрально, пул соответствует фильтрам. |
| L01-06 | Проверить журналы и snapshot при активной работе с весами | Чужие веса и токены приглашений не встречаются ни в ответах, ни в журналах. |
| L02-01 | Задать разным участникам веса, продвигающие разные категории, стартовать | Пул отсортирован по убыванию суммарных баллов; при равенстве сохранён порядок Discovery v1; состав и порядок одинаковы у всех участников. |
| L02-02 | Выставить всем участникам вес 0 одной категории | Кандидаты этой категории исключены из пула. Если исключено всё — `EXHAUSTED`, `round=null`. |
| L02-03 | Завершить раунд без большинства с лайками одной категории | Новый пул не содержит показанных карточек и ранжирован с учётом прибавок за лайки; прибавка не превышает потолок 5. |
| L02-04 | Конкурентно завершить раунд последними двумя участниками | Ровно один новый пул, одинаковый для всех. Повтор завершения возвращает текущий snapshot, голос в старый раунд — `409 STALE_ROUND`. |
| L02-05 | Комната, созданная до применения v2, стартует и проходит раунд | Поведение эквивалентно нейтральным весам, ошибок миграции нет. |
| L02-06 | Регрессия большинства | Строгое большинство определяется по правилам v1 и возвращает `result.kind=MAJORITY`. |
| L03-01 | Исчерпать кандидатов без большинства при наличии лайков | Комната в `MATCHED`, `result.kind=TOP_LIKED`, победитель — карточка с максимумом лайков по всем раундам. |
| L03-02 | Исчерпать кандидатов при равенстве лайков у двух карточек | Побеждает показанная раньше (ранний раунд, затем ранняя позиция). |
| L03-03 | Исчерпать кандидатов без единого лайка | `EXHAUSTED`, `round=null`, `result=null`. |
| L03-04 | Конкурентные завершения на границе исчерпания | Все участники видят один и тот же терминальный snapshot; повтор завершения возвращает его же. |
| L03-05 | Действия после терминального состояния | Голос, завершение и PUT весов — `409 INVALID_STATE`; `GET` стабильно возвращает итог, long poll не зависает. |
| L03-06 | Тайм-аут 30 минут до исчерпания | `CLOSED` по правилам v1, итог не вычисляется. |
| L03-07 | Переподключение после `TOP_LIKED` | `GET` возвращает терминальный snapshot с результатом; версия монотонна. |

В отчёте указать версию стенда, тестовые данные, фактические статусы и ссылки на неизменённые отчёты прогонов по [правилам тестирования](../../../workflow/rules/testing.md).
