# Спецификация разработки · Лента (мобильное приложение)

Спецификация только для мобильного клиента Android/iOS в KMP-модуле `shared`. Серверное поведение здесь не реализуется и не изменяется: API описаны в [контракте релиза](../../contracts/discovery-v1.md), серверная спецификация — у бэкендера ([BE-D03](../discovery-v1/implementation.md#be-d03--свайпы-на-одном-и-нескольких-устройствах)). Все упомянутые статусы, сроки и правила (TTL курсора, большинство, тайм-ауты) клиент принимает как данность контракта. Поведение экранов — в [описании дизайна ленты](../../design/feed.md). Применяются [правила проекта](../../../workflow/rules/index.md): слои `domain/data/presentation` на фичу, инверсия зависимостей, use case, DI через `di/AppContainer`, документация фичи в `FEATURE.md`.

Актуальные макеты: секция [«Лента · выбор мест и событий» (280-10678)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10678). Прототип пула: [«Лента · Пул из 10» (301-7832)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=301-7832), конец пула: [296-6572](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=296-6572).

## Компоненты UI Kit

Экраны собираются только из компонентов модуля `:uikit` (`ru.srastemsya.uikit`). Соответствие Figma → код:

| Figma | Компонент | Использование |
|---|---|---|
| `Navigation/TopBar` | `SrTopBar` | Заголовок экрана, кнопка «Назад» |
| `Navigation/TabBar` | `SrTabBar` / `SrNativeTabBar` | Вкладки Главная → Карта → Лента → События → Профиль |
| `Control/Chip` | `SrChip` | Тип подборки, категории, метка результата |
| `Field/Input`, `Field/Number`, `Field/Date` | `SrField`, `SrDateField` | Название комнаты, бюджет, дата |
| `Button/Actions` | `SrButton` | Основные действия экранов |
| `Identity/AvatarGroup` | `SrAvatarGroup` | Участники комнаты |
| `Room/Invite` | `SrRoomInvite` | Ссылка-приглашение, состояние «скопировано» |
| `Vote/PlaceCard` | `SrVoteCard` | Карточка места или события |
| `Vote/Actions` | `SrVoteActions` | Кнопки «пропустить», «отменить», «нравится» |
| `Vote/Result` | `SrVoteResult` | Полноэкранный результат |
| `Feedback/Status` | `SrStatus` | Ожидание голосов, «больше вариантов нет» |

Фон экранов — градиент Главной, карточки и панели — стиль `Surface / Liquid Glass` (`SrCard`/`Glass`). Новые цвета и радиусы не вводить: использовать токены `Theme.kt` (`color/surface/glass`, `color/border/glass`, `radius/24` и т.п.). При ограниченной поддержке стекла — подложка `color/surface/solid`.

## Доменная модель (общая для пакетов)

В `shared/.../feed/domain` (рефакторинг текущего `party`):

- `FeedKind { PLACE, EVENT }`, `FeedFilters(kind, categoryId?, localDate?, budgetTotalMinor?, partySize)` — зеркало query `GET /feed/candidates` и тела старта комнаты. Бюджет в копейках, трактуется как общий; цена карточки — на человека, проверка `price * partySize <= budgetTotal` включительная (серверная, клиент не дублирует).
- `FeedCard` — проекция `CatalogCard`: `ref(kind,id)`, title, категория, ценовая метка, адрес/дата, описание, URL обложки.
- `SwipeDecision { LIKE, SKIP }` — локальная модель решения; история решений с поддержкой отмены хранится на устройстве и не отправляется в одиночном режиме.
- `RoomSnapshot` — зеркало DTO `Room` из BE-04: фаза `LOBBY/VOTING/REFRESHING/MATCHED/EXHAUSTED/CLOSED`, участники, раунд, только свои голоса, `version`, `result.winner?`.
- Интерфейсы `FeedRepository` (одиночная выдача) и `RoomRepository` (комната, long polling) — в domain; реализации `BackendFeedRepository`, `BackendRoomRepository` — в data через общий `BackendApi`.

Use cases по одному на операцию: `GetFeedCandidatesUseCase`, `CreateRoomUseCase`, `CreateInviteUseCase`, `JoinRoomUseCase`, `StartRoomUseCase`, `SubmitVoteUseCase`, `CompleteRoundUseCase`, `ObserveRoomUseCase`.

## FE-F00 · Вход и выбор режима

Фреймы: [01 · Выбор устройства (280-10679)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10679)

Вкладка «Лента» таббара открывает экран «Выбираем вместе» с двумя карточками-опциями:

- **На одном устройстве** (`Icon/user`) — «Смотрите карточки вместе на одном телефоне и задайте общий бюджет» → FE-F01 в одиночном режиме.
- **На нескольких устройствах** (`Icon/users`) — «Создайте комнату и пригласите друзей. У каждого будет своя лента» → FE-F04.

Таббар виден только на этом экране сценария; все последующие шаги открываются поверх без таббара, с кнопкой «Назад» в `SrTopBar`. Вход «Свайпать события» с Главной открывает этот экран с предвыбранным `kind=EVENT` (пробрасывается в FE-F01). Экраны доступны только с завершённым профилем; `403 PROFILE_INCOMPLETE` ведёт на завершение регистрации.

## FE-F01 · Фильтры подборки

Фреймы: [04а · Общие фильтры (280-10774)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10774), [04б · Фильтры комнаты (280-10805)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10805)

Один экран «Что ищем?» с двумя вариантами подзаголовка: «Вы выбираете вместе на одном устройстве» и «Организатор задаёт фильтры для всей комнаты». Состав:

1. **Тип подборки** — чипы «Места / События» (единственный выбор). Для событий дополнительно доступна дата `Field/Date` (`localDate`); для мест поле даты скрыто или неактивно — `localDate` применим только к событиям.
2. **Категории** — чипы из `GET /catalog/categories`, фильтрация по `kinds`. «Все» = без `categoryId`. В Figma показаны три чипа-примера; реальный список серверный.
3. **Бюджет** — `Field/Number`, общий бюджет в рублях, конвертируется в `budgetTotalMinor`. В одиночном режиме вместе с бюджетом вводится число человек (`partySize`, целое от 1, обязателен при бюджете). В комнате `partySize` сервер нормализует до размера комнаты — поле не показывается.
4. Кнопка «Показать подборку» (одиночный) / «Начать выбор» (комната).

В комнате фильтры редактирует только организатор; участники на этом шаге остаются в лобби (FE-F04). «Изменить фильтры» со свайп-экрана возвращает сюда с текущими значениями; в комнате изменение фильтров после старта начинает новую комнату — показать подтверждение. Валидация: бюджет — неотрицательное целое, при заданном бюджете `partySize >= 1`. Ошибки полей — по паттернам UI Kit (красный контур + подпись).

## FE-F02 · Свайп-экран и стопка карточек

Фреймы: [05 · места (280-10836)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10836), [05 · события (280-10862)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10862), [06 · комната (280-10889)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10889), прототип жестов: [301-7832](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=301-7832)

Общий UI для обоих режимов, параметризуется контекстной строкой под топбаром:

- Одиночный: `Icon/users` + «Одно устройство · общий бюджет».
- Комната: «Комната: {название}» + `SrAvatarGroup` участников.

Состав: `SrTopBar` «Выбор места» / «Выбор события» с «Назад», иконка `Icon/filter` (44×44 зона нажатия) → FE-F01, стопка из активной `SrVoteCard` и двух декоративных подложек-карт (повороты ±3°, стекло `color/surface/glass`), `SrVoteActions`, счётчик позиции и шкала прогресса по текущему пулу.

Жесты и действия:

- Свайп влево или крестик — `SKIP`; свайп вправо или сердечко — `LIKE`. Анимация уводит карточку в сторону решения, следующая поднимается из стопки.
- «Отменить» возвращает предыдущую карточку и стирает её решение; доступна, пока есть локальная история в текущем пуле. Решения по текущему пулу можно менять до его завершения.
- Во время загрузки следующего пула действия скрыты (FE-F03/FE-F05).

`SrVoteCard`: обложка (серверный URL с плейсхолдером проекта при отсутствии), заголовок, чипы-метки (категория, ценовая метка `₽/₽₽/₽₽₽` или цена, адрес или дата), описание. Карточка целиком нажимается? — **Требует решения**; в макете переход в детали есть только с экрана результата.

Логика свайпов — в `FeedSwipeController` (presentation, общий для FE-F03 и FE-F05): хранит пул, индекс, решения, историю отмен; источники пула подключаются стратегией.

## FE-F03 · Одно устройство: пул и результат

Фреймы: [05 (280-10836, 280-10862)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10836), [07б · первая карточка нового пула (280-11023)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11023), [07в · загрузка (280-11049)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11049), [Выбрано (280-10985)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10985)

- Пул: `GET /feed/candidates` с query из `FeedFilters`, порции до 20, курсор живёт 30 минут, повтор курсора возвращает ту же порцию. Повторов карточек внутри сессии курсора нет; на `nextCursor=null` после последней карточки — FE-F06.
- **Первый лайк завершает выбор**: свайп-экран закрывается, открывается полноэкранный результат — обложка на всю ширину, чип «Вы выбрали», название, параметры, описание, кнопка «К месту» / «К мероприятию» → детали `GET /catalog/{kind}/{id}` (полный DTO читается этим запросом, карточки пула недостаточно).
- **Автообновление**: `SKIP` на последней карточке порции автоматически запрашивает следующую по `nextCursor`. На месте карточки — заглушка со скелетоном и спиннером, тексты «Обновляем подборку» и «Ищем новые варианты по вашим фильтрам», действия скрыты. Успех — первая карточка новой порции, счётчик продолжает сквозную нумерацию пула? — в макете счётчик сбрасывается на новую подборку; принять сброс счётчика на каждую порцию.
- Свайпы и отмена не отправляются на сервер; состояние пула переживает поворот экрана и уход вглубь приложения (сохранение в ViewModel/StateFlow), но не обязано переживать перезапуск процесса.

## FE-F04 · Комната: создание, приглашение, запуск

Фреймы: [02 · Создание (280-10707)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10707), [03 · Приглашение (280-10728)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10728), [03а · Скопировано (280-10751)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10751)

1. **Создание**: экран «Создайте комнату» — `Field/Input` названия (непустое после обрезки пробелов), кнопка «Создать» → `POST /rooms` с `Idempotency-Key` → `201`.
2. **Лобби организатора**: заголовок — название комнаты, подпись «Пригласите друзей, прежде чем начать выбор», `SrAvatarGroup` и счётчик «N участников подключились» (live через long polling), `SrRoomInvite` со ссылкой из `POST /rooms/{id}/invites` и кнопкой копирования. Состояние «скопировано» — компактный вариант `Room/Invite` с подтверждением. Ссылка многоразовая, живёт 30 минут; по истечении — перевыпуск новым POST.
3. **Вступление**: приглашённый открывает ссылку (deeplink), клиент извлекает `token` и вызывает `POST /room-invites/join`. Повтор входа участника возвращает snapshot; `410 INVITE_EXPIRED` новому участнику — сообщение с просьбой запросить новую ссылку. Участник видит лобби без кнопки старта и без управления фильтрами.
4. **Запуск**: кнопка «Начать выбор» активна при `участников >= 2`, ведёт организатора в FE-F01 (вариант 04б), затем старт комнаты телом `{filters}` (`budgetTotal: Money|null`). Ответ `EXHAUSTED` с `round=null` — сразу FE-F06. Участники получают старт через long polling и автоматически переходят на свайп-экран.

Long polling по контракту: один открытый `GET /rooms/{id}?afterVersion=&waitSeconds=25`, `204` — немедленный повтор, сетевая ошибка — повтор с задержкой, ответы со старой версией игнорируются, ожидание прекращается при уходе с экрана и в терминальном состоянии. Инкапсулировать в `ObserveRoomUseCase`/`RoomRepository`, наружу — `Flow<RoomSnapshot>`.

## FE-F05 · Комната: голосование, ожидание и матч

Фреймы: [06 (280-10889, 280-10916)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10889), [Ожидание (280-10964)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10964), [Матч большинства (280-11004)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11004)

- Каждый участник проходит весь зафиксированный пул раунда (до 20 карточек, одинаковый состав и порядок у всех). И лайк, и пропуск открывают следующую карточку; лайков может быть несколько. Голос — `PUT` решения по карточке; до завершения прохода решение можно заменить (отмена из FE-F02 повторяет `PUT` с новым значением).
- После решения по последней карточке — `POST` завершения прохода и экран ожидания «Ваш голос принят» с `SrStatus` и пояснением «Если большинство выберет один вариант, покажем его всем. Иначе обновим подборку». Кнопка возврата — «Назад» (просмотр, голос не меняется). Завершение с пробелами в решениях невозможно по UI; `409 INVALID_STATE` обрабатывается перезапросом snapshot.
- По snapshot `MATCHED` — полноэкранный результат с чипом «Матч большинства», данными `result.winner` и кнопкой «К месту»/«К мероприятию». Показывается всем участникам, включая находящихся на свайп-экране.
- Без большинства сервер открывает новый раунд — клиент показывает состояние загрузки «Обновляем подборку» (как FE-F03) и первую карточку нового пула; `EXHAUSTED` — FE-F06. Промежуточный `REFRESHING` отображается тем же состоянием загрузки.
- `409 STALE_ROUND` на голосе — перечитать snapshot и перейти к актуальному раунду. Переподключение: при возврате на экран читается свежий snapshot, восстанавливаются свои голоса и признак завершения. `CLOSED` по тайм-ауту 30 минут — заглушка «Комната закрыта» с выходом в FE-F00.

## FE-F06 · Исчерпание выдачи и ошибки

Фреймы: [08 · Больше вариантов нет (280-10943)](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10943), автопроверка: [280-11049](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11049)

- **Исчерпание**: `nextCursor=null` в одиночном режиме, `EXHAUSTED` комнаты или пустой первый ответ — экран «Больше вариантов нет» с `SrStatus`, текстом «Под ваши параметры больше нет подходящих мест и мероприятий» и кнопкой «Изменить фильтры» → FE-F01 текущего режима и типа подборки с сохранёнными значениями.
- **`409 CURSOR_EXPIRED`** — предложение обновить подборку; согласие запрашивает пул заново без курсора.
- **Сетевые ошибки** свайп-экрана: загрузка пула — состояние заглушки с ошибкой и повтором; ошибка голоса или завершения — повтор с тем же `Idempotency-Key`, UI не блокируется навсегда. Ошибки объявляются ассистивным технологиям, повторная отправка доступна после ошибки, на время запроса действие блокируется.
- `401 SESSION_EXPIRED` — стандартный refresh `BackendApi`, при неудаче — выход на вход. `404 NOT_FOUND` комнаты (посторонний или удалённая) — заглушка с возвратом в FE-F00.

## Требует решения

Наследуются из [описания дизайна](../../design/feed.md) и дополняются:

1. Переход в детали по тапу на карточку свайп-экрана (в макете только с результата).
2. Сквозной или сбрасываемый счётчик при автообновлении пула (принят сброс — подтвердить с дизайном).
3. Поведение при нескольких карточках с равным большинством решает сервер (более ранняя в пуле) — клиенту достаточно `result.winner`, подтверждено контрактом.
4. Выход участника из комнаты после старта отсутствует в API — UI не предлагает такого действия.

## Готовность пакета

Каждый пакет завершается: соответствием фреймам Figma на обоих платформах, `FEATURE.md` в директории фичи, unit-тестами use case и ViewModel (решения, отмена, границы пула, конечный автомат комнаты), обновлением `docs/frontend-implementation.md` при смене привязок DI. Приёмка сценариев комнаты сверяется с D03-* из [приёмки discovery-v1](../discovery-v1/acceptance.md).
