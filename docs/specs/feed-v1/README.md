# Мобильный релиз «Лента»: выбор мест и событий

Очередь спецификаций мобильного приложения (Android/iOS, KMP) для вкладки «Лента». Только клиентская работа: серверная часть описывается отдельной спецификацией бэкенда ([BE-D03](../discovery-v1/implementation.md#be-d03--свайпы-на-одном-и-нескольких-устройствах)) и в этот объём не входит. Граница между клиентом и сервером — [HTTP-контракт](../../contracts/discovery-v1.md); все обращения к серверу в пакетах ниже означают вызовы этого контракта, а не задачи на его реализацию. Основана на актуальной секции Figma [«Лента · выбор мест и событий»](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10678) и [UI Kit · Liquid Glass](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-8378).

## Очередь пакетов

| Пакет | Результат | Зависимости |
|---|---|---|
| [FE-F00](implementation.md#fe-f00--вход-и-выбор-режима) | Вкладка «Лента», выбор «одно / несколько устройств» | UI Kit `:uikit`, навигация приложения |
| [FE-F01](implementation.md#fe-f01--фильтры-подборки) | Экран фильтров для обоих режимов, модель `FeedFilters` | FE-F00 |
| [FE-F02](implementation.md#fe-f02--свайп-экран-и-стопка-карточек) | Стопка карточек, свайпы, отмена, счётчик | FE-F01 |
| [FE-F03](implementation.md#fe-f03--одно-устройство-пул-и-результат) | Одиночная выдача `GET /feed/candidates`, автообновление пула, результат первого лайка | FE-F02, готовый стенд BE-D03 |
| [FE-F04](implementation.md#fe-f04--комната-создание-приглашение-запуск) | Создание комнаты, приглашение по ссылке, лобби | FE-F01, готовый стенд BE-D03 |
| [FE-F05](implementation.md#fe-f05--комната-голосование-ожидание-и-матч) | Голосование в раунде, ожидание, матч большинства, новый раунд | FE-F02, FE-F04 |
| [FE-F06](implementation.md#fe-f06--исчерпание-выдачи-и-ошибки) | «Больше вариантов нет», `CURSOR_EXPIRED`, сетевые ошибки, offline-поведение | FE-F03, FE-F05 |

Пакеты FE-F03 и FE-F04 независимы и могут идти параллельно после FE-F02. Зависимость от BE-D03 — только наличие работающего стенда для интеграции и приёмки; до его готовности разработка и ручная проверка идут на `MockPartyRepository`, приёмка проводится против стенда. Существующая фича `shared/.../party` рефакторится под эти спецификации, а не переписывается с нуля. Вопросы к поведению сервера (сроки курсора, правило большинства, тайм-аут комнаты) решаются в контракте и спецификации бэкенда, а не здесь.
