# Лента

Помогает компании выбрать место или мероприятие. Одиночный выбор открывается с Главной, комнатный — через создание комнаты или приглашение; отдельной вкладки «Лента» в навигации нет. [Актуальная секция в Figma](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10678) · [прежняя секция](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=182-4076). Клиентская очередь спецификаций — [feed-v1](../specs/feed-v1/README.md).

### FE-F03 · одно устройство: пул и результат

Точки дизайна: [первая карточка](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10836), [событие](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10862), [обновление](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11049), [выбрано](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10985). Пакет использует группу «Лента · выбор мест и событий» и существующие компоненты UI Kit.

- **Назначение:** помочь компании быстро выбрать место или событие без долгого обсуждения. Во время запроса следующей порции действия скрыты, чтобы свайп не изменил позицию до ответа.
- **Точки входа:** Главная → «Свайпать события» → «На одном устройстве» → фильтры → «Показать подборку».
- **Состояния:** карточка с позицией и подсказкой «← Нет · Да →»; обновление с текстами «Обновляем подборку» и «Ищем новые варианты по вашим фильтрам»; «Больше вариантов нет» с возвратом к фильтрам; после выбора событие открывает общую страницу «О событии», место — подробности каталога, обе страницы дают перейти на Главную.
- **Переходы:** свайп вправо («Да») завершает выбор: событие открывается на общем экране «О событии», место — в подробностях каталога; оттуда можно перейти на Главную. Свайп влево («Нет») пропускает карточку. Пропуск последнего кандидата автоматически запрашивает следующую порцию по тем же фильтрам и курсору. При исчерпании кнопка возвращает к фильтрам текущего типа с сохранёнными значениями.
- **Сценарий:** выбрать тип и фильтры, пропускать карточки до выбора или автоматической загрузки, затем открыть результат или скорректировать фильтры при исчерпании.
- **Прототип и реализация:** API-контракт отдаёт до 20 кандидатов; Android показывает их локальными частями по 10. Счётчик части сбрасывается при переходе к следующим 10 карточкам и новой порции API. Подробности загружаются отдельно по `CatalogRef`; процессный перезапуск не восстанавливает выдачу.

## Поведение

1. В режиме одного устройства компания сразу выбирает фильтры и указывает общий бюджет. В режиме комнаты организатор создаёт её, приглашает участников, задаёт фильтры и запускает подборку. После запуска каждый голосует со своего устройства.
2. Тип подборки «Места / События» меняется в фильтрах. Экран выбора показывает одну активную карточку, счётчик, шкалу прогресса и действия. Свайп влево или крестик пропускает карточку. Свайп вправо или сердечко ставит лайк. Пока решение по текущему варианту можно изменить, отмена возвращает предыдущую карточку.
3. **Одно устройство.** Первый лайк завершает выбор и сразу открывает полноэкранную карточку выбранного места или события. Если весь пул пропущен, загрузить следующие варианты по тем же фильтрам.
4. **Несколько устройств.** Каждый участник проходит весь общий пул на своём устройстве и может лайкнуть несколько карточек. И лайк, и пропуск открывают следующую карточку. После решения по последней карточке участник завершает свой проход и ждёт остальных. Когда все участники завершили проход, подсчитать лайки отдельно по каждой карточке. Для комнаты v2 сервер показывает `THRESHOLD`, когда хотя бы один вариант получил не меньше 70% лайков от фиксированного числа участников (`likes * 10 >= memberCount * 7`); результат один для всей комнаты. Если порог не достигнут, сервер открывает следующий пул до 10 карточек без повторов. При исчерпании после хотя бы одного лайка сервер показывает лидера с `basis=TOP_SCORE`; при нуле лайков — `EXHAUSTED`.
5. **Обновление.** После свайпа влево на последней карточке без выбора (или после комнатного раунда без порога 70%) автоматически запросить следующий пул по тем же фильтрам. На месте карточки показать заглушку с индикатором загрузки и текстом «Обновляем подборку». На время запроса действия с карточкой скрыты. Если есть новые варианты, автоматически показать первую карточку нового пула и сбросить счётчик. Если выдача исчерпана, показать «Больше вариантов нет» с пояснением и кнопкой «Изменить фильтры». Кнопка возвращает к фильтрам текущего режима и типа подборки.
6. **Результат.** Событие открывается на общем экране «О событии», место — на подробностях места; обе страницы предлагают переход на Главную.

## Прототип и оформление

В Figma крестик на последней карточке мест в режиме одного устройства имитирует свайп влево. После него новая карточка появляется автоматически. Если пропустить и её, прототип через то же состояние загрузки автоматически открывает заглушку. Экран ожидания и карточка матча в Figma показывают состояния комнаты. При реализации ожидание открывается после последней карточки участника, а результат рассчитывается после завершения раунда. Для «Сапов на Тобизина» кнопка ведёт к [деталям события](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=33-1647). Остальные карточки показывают внешний вид результата и подписи кнопок.

Вся Лента использует фон с градиентом Главной, а карточки и действия собраны из компонентов UI-кита. [UI Kit · Liquid Glass](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=69-583)

**Уточнение room-v2:** сервер выбирает среди нескольких карточек, достигших порога 70%, по числу лайков и затем по порядку пула; состав фиксируется на раунд. Голос можно заменить до завершения своего прохода. Каждый раунд истекает через 30 минут и закрывает незавершённую комнату. Старое правило макета «больше половины» для комнаты v2 заменено контрактом `lobby-v2.md` из архива frontend API от 2026-11-13.


## Комната: создание, приглашение и лобби (FE-F04 Android)

Сценарий для друзей, выбирающих с разных устройств: организатор задаёт имя комнаты, получает ссылку и ждёт участников; приглашённый открывает ссылку и видит тот же состав. Это снижает риск начать выбор без друга и помогает заметить, что приглашение истекло. Вход — карточка «На нескольких устройствах» в Ленте или deeplink.

1. [Создание](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10707): поле названия и кнопка «Создать комнату». Пустое название блокирует создание.
2. [Приглашение](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10728): название, группа аватаров с инициалами и число участников, встроенная карточка приглашения без отображения сырого URL. Организатор получает ссылку после создания комнаты и переходит к фильтрам при двух участниках. Состав обновляется автоматически. Приглашённый видит ожидание без управления стартом.
3. [Скопировано](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10751): после копирования карточка заменяется компактным подтверждением без кнопки.
4. Истёкшая ссылка показывает просьбу получить новую; экран остаётся доступным. Повторный вход участника возвращает его в текущую комнату. «Назад» закрывает лобби и останавливает обновления.
5. Организатор задаёт тип, дату события и общий бюджет на шаге фильтров и запускает комнату. Число участников берётся из состава комнаты и в фильтрах не вводится. После ответа показывается число карточек пула; свайпы и голосование реализуются отдельным пакетом.

Для прогона экранов 10–13: [создание](../specs/swipe-ui/10-room-create.md) → [приглашение](../specs/swipe-ui/11-room-invite.md) → [подтверждение копирования](../specs/swipe-ui/12-room-copied.md) → [фильтры](../specs/swipe-ui/13-room-filters.md). Создатель вводит имя, получает ссылку, копирует её и открывает фильтры после подключения второго участника. Пустое имя показывает ошибку поля UI Kit. Длинное имя в лобби ограничено двумя строками. Категории загружаются из каталога, дата доступна для событий. **Требует решения:** фрейм фильтров показывает персональный бюджет и подразумевает отправку каждым участником, но действующий room API принимает общий бюджет и запускается организатором. Персональная подпись, кнопка отправки и ожидание участников требуют макета и серверного контракта; текущий экран сохраняет точную семантику общего бюджета.

Прототип показывает визуальные состояния создания и копирования; в приложении ссылка приходит от сервера и состав обновляется long polling. Токены и компоненты — `SrTopBar`, `SrField`, `SrButton`, `SrChip`, `SrColors`, `FeedDesign.ScreenGradient`.

### FE-F05 · Комнатный раунд на Android

Участники из лобби переходят к общему пулу голосования: [голосование](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10889), [ожидание](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10964), [матч](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11004). Сценарий предназначен друзьям, которые выбирают место или событие вместе: каждый проходит одни и те же карточки, подтверждает проход, ждёт остальных и видит общий серверный итог. До завершения голос можно заменить. Экран ожидания позволяет просмотреть только свои решения. При отсутствии порога 70% сервер даёт новый пул без повторов; при исчерпании с хотя бы одним лайком показывает `TOP_SCORE`, без лайков — `EXHAUSTED`. При истечении 30 минут текущего раунда комната закрывается с выходом к выбору режима. Матч открывает сведения выбранного объекта. UI следует состоянию room-v2 snapshot, включая номер раунда, срок, фиксированное число участников и результат `{winner,basis: THRESHOLD|TOP_SCORE,likes,memberCount}`, а не рассчитывает итог из локальных голосов.
