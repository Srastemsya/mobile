# Внутренняя интеграция каталога Discovery v1

В сети Compose swipes при создании пула вызывает `GET http://catalog:8000/internal/catalog/candidates` с Bearer JWT инициатора с завершённым профилем. Nginx не публикует внутренние маршруты. Параметры `kind`, `categoryId`, `localDate`, `budgetTotalMinor`, `partySize` соответствуют [фильтрам кандидатов](discovery-v1.md#свайпы-на-одном-устройстве). Ответ `200 {items: CatalogCard[]}` содержит весь подходящий снимок в стабильном порядке. Для событий порядок `startsAt, id`, для мест — `id`. Запрос читает актуальные данные каталога, чтобы новый пул увидел успешную публикацию. Swipes сохраняет снимок одиночной выдачи и разбивает его на страницы. Для нового комнатного раунда swipes читает актуальный снимок и исключает уже показанные карточки. Синхронное чтение позволяет учесть публикации, зафиксированные перед запросом нового пула.

Для страницы списка записей catalog запрашивает у identity один пакет публичных данных участников. `GET http://identity:8000/internal/identity/participants?id=…&id=…` принимает до 20 ID и сессию инициатора с завершённым профилем. Ответ `200 {items: [{id, displayName, avatar}]}`. Это чтение выполняется после проверки прав организатора и возвращает текущие имена без копирования профилей между БД.

При создании комнаты или первом вступлении swipes использует тот же внутренний маршрут identity для получения имени одного участника. Swipes сохраняет имя в составе комнаты вместе с ID. Room snapshot содержит решения только текущего участника.

Внутренний канал Redis Pub/Sub `room:{id}` передаёт версию комнаты после фиксации в PostgreSQL. Тело сообщения содержит только номер версии. Канал ускоряет чтение актуального snapshot и обслуживает ожидание в пределах одного сервиса. Межсервисные события каталога по-прежнему доставляет Kafka.

## Kafka

Catalog владеет темой `catalog.changed.v1` и публикует JSON с ключом `objectId`. Сообщение содержит `eventId` (уникальный ID сообщения), `type: CATALOG_OBJECT_CHANGED`, `kind: EVENT`, `objectId`, `revision` (монотонное целое каталога), `occurredAt` (UTC). Событие создаётся при публикации, создании или снятии записи. События не содержат пользовательских данных.

Изменение объекта, ревизия и запись outbox фиксируются одной транзакцией. Доставка допускает повторы; потребитель каталога идемпотентно удаляет затронутые ключи прежней ревизии Redis. TTL удаляет невостребованные ключи, а переключение ключей по ревизии PostgreSQL даёт немедленную видимость независимо от задержки Kafka. При недоступности Kafka HTTP-операции продолжаются с накоплением outbox.
