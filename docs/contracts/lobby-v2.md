# Контракт комнаты v2 · весовой выбор в лобби

Надстройка над разделами «Свайпы в комнате» и «Long polling» [контракта Discovery v1](discovery-v1.md). Имена DTO, авторизация, ошибки и идемпотентность наследуются из [мобильного API](mobile-api.md). При расхождении для комнат действует этот документ. Версия относится только к комнатам; одиночная выдача не меняется.

## Изменения DTO

- `Room.members[]` дополняется `hasPreferences: boolean`.
- `Room.preferences: [{categoryId, weight}] | null` — только собственные веса текущего участника, по аналогии с голосами. Чужие веса в snapshot не раскрываются.
- `Room.result: {winner: CatalogRef, kind: MAJORITY | TOP_LIKED} | null`. `MAJORITY` — строгое большинство по правилам v1, `TOP_LIKED` — итог при исчерпании (BE-L03).
- Остальные поля `Room`, `Round` и коды ошибок — как в v1.

## Веса в лобби

`PUT /rooms/{id}/preferences` с телом `{weights: [{categoryId: string, weight: integer}]}` → `200 Room`.

- Доступно любому участнику только в `LOBBY`. После старта — `409 INVALID_STATE`. Посторонний — `404 NOT_FOUND`.
- Запрос заменяет собственный набор целиком. `weight` — целое 0–3. Неизвестный `categoryId`, дубль категории или вес вне диапазона — `422 VALIDATION_ERROR` с указанием поля.
- Повтор с тем же результирующим набором не меняет `version`. Фактическое изменение поднимает `version` и пробуждает long poll остальных участников; токены и чужие веса в snapshot не попадают.

## Построение пула по весам

- Эффективный вес участника по категории: заданный вес, иначе нейтральный `1`. Участник без отправленных весов нейтрален по всем категориям.
- Балл кандидата = сумма эффективных весов всех участников по категории кандидата. Кандидаты с баллом `0` исключаются из пула.
- Пул раунда — до 20 кандидатов по убыванию балла; при равенстве — порядок выдачи Discovery v1. Состав и порядок фиксируются на старте и одинаковы для всех, как в v1.
- Старт (`POST /rooms/{id}/start`) не меняет маршрут и тело; минимум два участника. Фильтры комнаты применяются до весового ранжирования. Пустой пул на старте — `EXHAUSTED`, `round=null`, как в v1.

## Следующий пул (после раунда без большинства)

- Веса пересчитываются перед каждым новым раундом: к базовому весу участника по категории добавляется `+1` за каждый его лайк карточки этой категории в завершённых раундах комнаты; итог ограничивается `5`. Базовые веса после старта не редактируются (`PUT /preferences` → `409 INVALID_STATE`).
- Новый пул строится по пересчитанным баллам без повторов ранее показанных карточек. Переход, `REFRESHING`, `409 STALE_ROUND` и конкурентные завершения — по правилам v1.

## Итог при исчерпании

- Если после завершённого раунда большинства нет и новых кандидатов не осталось, но в комнате есть хотя бы один лайк за всю её историю, комната переходит в `MATCHED` с `result.kind=TOP_LIKED`. Побеждает карточка с максимальным суммарным числом лайков по всем раундам; при равенстве — показанная раньше (более ранний раунд, затем более ранняя позиция в пуле).
- Если лайков не было ни одного — `EXHAUSTED`, `round=null`, `result=null`, как в v1.
- Терминальные состояния стабильны: повторные чтения и переподключения возвращают тот же результат, голос и завершение в терминальном состоянии — `409 INVALID_STATE`. Тайм-аут 30 минут и `CLOSED` действуют как в v1; после `CLOSED` итог не вычисляется.

## Long polling

Без изменений относительно v1. Изменение весов в `LOBBY`, пересчёт пула и терминальные состояния доставляются тем же механизмом версий.

## Решения для согласования

Диапазон весов 0–3, нейтральный вес 1, прибавка `+1` за лайк с потолком 5 и правило более ранней карточки при равенстве лайков — рабочие значения стенда; подтвердить перед выпуском. Отдельный UI выбора весов описывается дизайном комнаты и в этот контракт не входит.
