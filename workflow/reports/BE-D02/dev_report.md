# BE-D02 · Отчёт разработчика

Кандидат `d3d76991309ebb180278605d46d8e11c6f4e7380` на базе `c754a31`. Сборка catalog `sha256:b4e59c4fc70c825223d8343725dc09deb8dfa1638513e91a8f84c08819a20239`. Локальный стенд `srastemsya-be-d02` с портом Nginx 18085.

- Афиша, карта, поиск, главная и внутренний снимок используют карточку из одного объекта каталога. Детали события одинаковы в обоих публичных маршрутах для одной сессии. При публикации собственник определяется по JWT. Время хранится в PostgreSQL как `timestamptz`, зона отдельно. Афиша и список записей используют курсор Redis с TTL 30 минут.
- Публикация и регистрация сохраняют результат идемпотентности в PostgreSQL в той же транзакции. Запись и снятие блокируют строку события перед чтением вместимости. Уникальная пара событие–пользователь удерживает статус снятия. Изменения и записи outbox фиксируются совместно.
- Kafka доставляет изменения с возможностью повтора. Удаление ключей Redis идемпотентно. Транзакционная ревизия переключает ключи сразу, даже если брокер временно недоступен. Каталог использует собственную БД и существующие Redis ACL, readiness и admin JWT. Для снимка нового пула и одного пакетного чтения имён участников предусмотрены отдельные внутренние HTTP-вызовы с проверкой сессии. Nginx сохраняет действующее разделение маршрутов.
