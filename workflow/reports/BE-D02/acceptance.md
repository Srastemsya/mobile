# BE-D02 · Критерии приёмки

Пакет с кодом. Основания: [реализация](../../../docs/specs/discovery-v1/implementation.md), [приёмка релиза](../../../docs/specs/discovery-v1/acceptance.md), [Discovery v1](../../../docs/contracts/discovery-v1.md), [мобильный контракт](../../../docs/contracts/mobile-api.md), [зависимости](../../../docs/specs/discovery-v1/README.md).

| ID | Основание | Проверяемый результат |
|---|---|---|
| AC-01 | D02-01 | Публикация и точный повтор возвращают один ID и исходный статус. Изменённое тело с прежним ключом даёт 409 IDEMPOTENCY_CONFLICT. Другой аккаунт сразу видит ровно одну подходящую карточку в афише и на карте. Свежий внутренний снимок кандидатов содержит её. Сквозная публичная выдача свайпов проверяется в BE-D03 по порядку релиза. |
| AC-02 | D02-02 | OPEN с вместимостью, REGISTRATION без положительной целой вместимости, платная запись, неверные координаты, категория, времена и чужая обложка отклоняются без публикации. Валидный OPEN не содержит счётчиков, REGISTRATION начинает с нуля подтверждённых. Проверить обязательные поля и информационную цену OPEN. Принятие собственной готовой EVENT_COVER зависит от BE-05, проверка на локальном стенде возможна с документированными синтетическими готовыми медиа. Загрузка файлов по протоколу BE-05 входит в зависимость. |
| AC-03 | D02-03 | Владивостокская граница суток, потолок цены исключает неизвестную цену, фильтр мест оставляет REGISTRATION с остатком, пагинация стабильна без дублей. |
| AC-04 | D02-04 | Конкурентная запись на последнее место даёт ровно один 201 и один 409 EVENT_FULL со счётчиками. Точный повтор победителя воспроизводит исходный ответ, новый ключ возвращает ту же запись с 200, остаток нулевой. |
| AC-05 | D02-05 | Посторонний получает 403 на чтение списка и снятие. Повтор снятия владельцем освобождает одно место суммарно, участник пропадает из активного списка и получает 409 REGISTRATION_REMOVED при повторной записи. |
| AC-06 | D02-06 | Точные границы UPCOMING, ONGOING, PAST. В момент старта canRegister=false и 409 EVENT_CLOSED. Допустим документированный управляемый dev-час или проверяемые данные с заданными границами. |
| AC-07 | INT-00, INT-01, INT-02 | На чистом изолированном стенде документированный запуск и повтор запуска готовы без дублей, существующие identity и catalog и новые маршруты работают через Nginx. Комнаты относятся к BE-D03. Порты БД, Redis и Kafka закрыты. Защищённые маршруты дают 401 без токена и 403 для незавершённого профиля. Остановка и восстановление БД каталога дают 503 и 200, секреты отсутствуют в ответах и логах. |
| AC-08 | Сервисы и локальный запуск | Developer предоставляет автоматизированную проверку архитектурных обязательств пакета, включая единую проекцию каталога, атомарную запись и outbox, Kafka и инвалидацию кэша. HTTP-проверки дополняются проверкой опубликованного интерфейса событий и регрессией BE-D01. |
