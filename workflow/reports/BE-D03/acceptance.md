# BE-D03 · Immutable acceptance

Source: docs/specs/discovery-v1/acceptance.md and implementation.md (BE-D03), docs/contracts/discovery-v1.md, docs/contracts/mobile-api.md.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| AC-01 · D03-01 | Запросить EVENT и PLACE с бюджетом, включая кандидата ровно по бюджету и кандидата с неизвестной ценой | Выдаётся выбранный тип. Граничная цена проходит, неизвестная исключается. Без бюджета неизвестная цена допустима. |
| AC-02 · D03-02 | Пройти все страницы выдачи, повторить курсор, затем использовать его после истечения | Страницы не пересекаются, повтор даёт ту же порцию, последняя страница содержит `nextCursor=null`. Истёкший курсор даёт `409 CURSOR_EXPIRED`. |
| AC-03 · D03-03 | Создать комнату, пригласить четырёх участников всего, запустить. Прочитать комнату посторонним | Все участники видят одинаковый пул и зафиксированный состав. Посторонний получает `404`. Новый участник после запуска не входит. |
| AC-04 · D03-04 | Попытаться завершить неполный проход. Изменить голос, завершить полный проход, переподключиться | Неполный проход даёт `409 INVALID_STATE`. После завершения голос не меняется. GET восстанавливает свой последний выбор и признак завершения без чужих голосов. |
| AC-05 · D03-05 | Дать одной карточке два лайка из четырёх, завершить раунд конкурентными запросами | Матча нет. Появляется один новый пул без ранее показанных карточек либо `EXHAUSTED` при пустой выдаче. Повтор завершения возвращает текущий snapshot. Новый голос по старому раунду даёт `409 STALE_ROUND`. |
| AC-06 · D03-06 | Дать двум карточкам по три лайка. Последние два участника завершают проход параллельно | Все видят один и тот же `MATCHED`. Побеждает более ранняя из карточек. При различии голосов выигрывает карточка с большим числом лайков. |
| AC-07 · D03-07 | Отключить участника до завершения, переподключиться, затем дождаться срока комнаты без завершения | Состав не меняется. После 30 минут GET возвращает `CLOSED`, голосование не меняет состояние. |
| AC-08 · D03-08 | Открыть long poll организатора через Nginx, вступить со второго устройства по ссылке | Ожидание завершается `200 Room` с большей версией и новым участником. Токена приглашения в ответе нет. |
| AC-09 · D03-09 | Открыть long poll на текущей версии, проголосовать или завершить раунд параллельным запросом | Ожидающий клиент получает обновлённую версию. При повторном запросе со старой версией ответ приходит сразу. Личные голоса другого участника отсутствуют. |
| AC-10 · D03-10 | Держать long poll без изменений до 25 секунд, затем повторить. Проверить запрос постороннего и отзыв сессии во время ожидания | Nginx пропускает `204` без тела, следующий запрос работает. Посторонний получает `404` сразу. Отозванная сессия получает `401` при завершении ожидания. |
| AC-11 · INT-00 | Выполнить документированную команду Compose на чистом локальном окружении, затем повторить запуск | Все сервисы готовы, миграции и dev-данные применены без дублей. Регистрация, афиша и комнаты доступны через Nginx. PostgreSQL, Redis и Kafka не публикуют порты наружу. |
| AC-12 · INT-01 | Запросить защищённые маршруты без токена и с незавершённым профилем | `401 UNAUTHENTICATED` и `403 PROFILE_INCOMPLETE` соответственно. |
| AC-13 · INT-02 | Отключить собственную БД на изолированном стенде и восстановить её | `/health` возвращает 503 во время недоступности и 200 после восстановления. В ответе и журналах нет учётных данных. |
