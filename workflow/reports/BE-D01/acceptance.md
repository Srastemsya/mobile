# BE-D01 · Приёмка
Источники: docs/specs/discovery-v1/implementation.md (§ BE-D01, сервисы и локальный запуск), docs/specs/discovery-v1/acceptance.md, docs/contracts/discovery-v1.md, docs/contracts/mobile-api.md.

- AC-01 (D01-01). Через Nginx открытия без координат возвращают 200, стабильный порядок подборок, поиск по фильтрам первой подборки выдаёт только подходящие карточки. Пустая выдача успешна и содержит пустые массивы.
- AC-02 (D01-02). Один EVENT/id и согласованные координаты и детали по обоим публичным маршрутам для одного зрителя. Категория в справочнике.
- AC-03 (BE-D01, HTTP-контракт). Справочник, детали по CatalogRef, фильтрация карты по границам, опубликованность, поля зрителя и доступные типы каталога соответствуют контракту. Невалидные запросы проверяются по контракту.
- AC-04 (INT-01). На реализованных защищённых маршрутах без токена 401 UNAUTHENTICATED, с незавершённым профилем 403 PROFILE_INCOMPLETE.
- AC-05 (INT-00 в границах пакета). Чистый изолированный Compose и повторный запуск готовы, миграции и стендовые данные без дублей, наружу публикуется только Nginx. Уже реализованные регистрация и комнаты доступны через Nginx.
- AC-06 (INT-02). Readiness catalog возвращает 503 при отказе собственной БД и 200 после восстановления, без учётных данных в ответе и журналах.
- AC-07 (BE-D01, правила MatchWear). Developer подтверждает проверками владение данными, единую проекцию, актуальность полей зрителя/вместимости, инвалидацию затронутого Redis-кэша, готовность и сохранение правил эксплуатации. Публикация и запись относятся к BE-D02.
