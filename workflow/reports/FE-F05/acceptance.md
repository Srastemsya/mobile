## Criteria

- **AC-01 — Shared round and personal votes.** Both room members see the same frozen candidate set in the same order (room-v2 pool at most 10). LIKE or PASS records a decision for the current candidate and advances. A participant can change a decision before finishing; only that member's votes are visible in their snapshot. Source: [FE-F05](../../specs/feed-v1/FE-F05.md), archived contract `docs/contracts/lobby-v2.md` (“DTO комнаты v2”, “Пул раунда”), [feed design](../../../docs/design/feed.md).
- **AC-02 — Match threshold and result.** After every participant finishes, show a match only when a candidate receives at least 70% of fixed round membership's likes (`likes * 10 >= memberCount * 7`). Render server winner and match metadata; all participants converge to the same result, including those viewing the stack. Never infer matches from local votes. Source: archived `docs/contracts/lobby-v2.md` (“DTO комнаты v2”, “Порог матча”); [Discovery v1](../../../docs/contracts/discovery-v1.md#свайпы-в-комнате); FE-F05.
- **AC-03 — No threshold and next round.** If no candidate reaches 70%, show refreshing then the next server-provided pool without duplicating prior candidates; preserve supported round number/expiration metadata. If exhausted, route to FE-F06. Source: archived `docs/contracts/lobby-v2.md` (“Пул раунда”, “Порог матча”, “Срок раунда”); FE-F05.
- **AC-04 — Wait, restore and close.** A first finisher sees “Ваш голос принят”; review does not change votes. After process death/relaunch, restore own votes and waiting/finished state from live snapshot without revealing others' votes. An expired 30-minute round closes the room, disables voting and allows exit to mode selection. Source: FE-F05 acceptance F05-03/F05-04; archived `docs/contracts/lobby-v2.md` (“Срок раунда”); [Discovery v1](../../../docs/contracts/discovery-v1.md#свайпы-в-комнате).
- **AC-05 — Live API resilience.** Snapshot and long-poll updates drive state; stale responses cannot roll state backward; stale-round/invalid-state errors recover by rereading live snapshot. Long polling stops when leaving room and resumes from a fresh snapshot on return. Source: [Discovery v1 long polling](../../../docs/contracts/discovery-v1.md#long-polling-комнаты-и-приглашения), FE-F05.
- **AC-06 — Android usability/design.** Check voting, waiting, refresh, match and closed-room states against [Feed page 2, node 280-7618](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-7618), and FE-F05 [voting](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10889), [waiting](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-10964), [match](https://www.figma.com/design/khewsPf7b4JVyBwJaCmO43/startap_design?node-id=280-11004) frames. Match action opens expected place/event. Relevant route: friends coordinate and vote for an activity (journey C in [personas](../../../docs/design/ux-personas-scenarios.md#4-пользовательские-сценарии-user-journeys)).
